Deploy ADK agents from one file.

You build the agent with agents-cli. You describe where and how it runs in agent.yaml. agentless works out what changed against what's deployed on Agent Runtime or Cloud Run and applies only that: service account, IAM, reasoning engine or Cloud Run service, Memory Bank, networking, Gemini Enterprise and Agent Registry. Then it evaluates what it deployed.

Get started agent.yaml reference
$brew install Aymen2518/tap/agentless

Three tools, one file

        
Deploying an agent used to mean a Terraform module per agent, a dozen agents-cli deploy flags living in someone's shell history, and a separate publish step. Labels and Memory Bank weren't exposed anywhere, and nothing showed what a deploy would change.

        
Now it's one declarative file per agent, with stages and variables, and one command that reconciles the cloud with it.

      

      

        
deployment/terraform/
resource "google_service_account" "agent" {…}
resource "google_project_iam_member" "x" {…}
resource "google_storage_bucket" "b" {…}
resource "google_vertex_ai_reasoning_engine"…

        
DEPLOYMENT.md
agents-cli deploy \
  --service-account sa-…@….iam \
  --update-env-vars LOG_LEVEL=info,… \
  --secrets SLACK_TOKEN=slack-token:latest \
  --min-instances 0 --max-instances 5 …

        
publish.sh
agents-cli publish gemini-enterprise \
  --app acme-assistant --engine $ENGINE_ID

provider: { project: ${param:project} }

Applied in order, removed in reverse

    
Nine steps, always in the same order, each skipped when agent.yaml doesn't use it. On Cloud Run, a build and a service replace the engine. A service account is never deleted while it still has bindings, and remove deletes only what the state record says agentless created.

2agentIdentitybare engine that mints the Agent Identity principal

Everything an agent deploy needs

  
The things that used to be split between Terraform, deploy flags and a publish script, in one file that agentless owns end to end.

  

    
Agent Runtime or Cloud Run
provider.name: cloud-run deploys the same agent as a Cloud Run service. It's built with Cloud Build, pinned by digest, and given a session engine for sessions and Memory Bank, plus ingress, IAP and Direct VPC egress.

    
Public, still behind IAM
cloudRun.auth: googleToken opens a Cloud Run agent to callers outside your network with two checks. Cloud Run IAM verifies the ID token, and your app verifies the Google token in x-google-token. Never allUsers. For GitLab or GitHub webhooks, auth: webhook gates the service on a shared secret instead, and agentless proves anonymous calls are refused after every rollout.

    
A real plan
agentless plan diffs every resource before anything changes. --detailed-exitcode exits 2 when there's work to do, for CI.

    
Minimal engine updates
Config changes go out with an update_mask and no rebuild. Code is rebuilt only when the source hash changes.

    
IAM it won't overreach
Read-modify-write with etag retries. agentless removes only the members it added. Existing bindings show as "not managed".

    
Three identity types
The platform service agent, a service account it creates or one you reference, or an Agent Identity principal (preview).

    
Buckets without data loss
Declare the buckets an agent writes to. Access is granted automatically, and data is never deleted on remove.

    
Tracing, logs, metrics
Cloud Trace is on by default, with its roles granted for you. logs, metrics and open traces read it back.

    
Memory Bank and sessions
Sessions mode, an artifacts bucket, and Memory Bank models, TTL and topics, set from the memory block.

    
Gemini Enterprise publishing
ADK or A2A registration in a GE app, with sharing, an egress Agent Gateway and an optional OAuth authorization. No separate publish step.

    
Evaluate what you deployed
agentless eval scores the live engine on the Evaluation Service and exits 1 below a threshold. deploy --eval makes it a gate.

    
Online monitors
Evaluators that sample live traces and score them continuously. Declared in evaluation.monitors, suspended with enabled: false.

    
Agent Registry for A2A
The agent card is read from the deployed engine and registered where Agent Gateways govern it. plan shows card drift.

    
Who can call this agent
access.invokers are granted on the engine, not the project, so they reach this agent and no other. Removing one revokes it. On Cloud Run, they get roles/run.invoker on the service.

    
Private networking and CMEK
PSC-I with DNS peering, and customer-managed keys. Immutable changes stop the plan (✋) unless you pass --allow-replace.

    
Variables from anywhere
Serverless syntax plus ${secret:} from Secret Manager and ${tf(gs://…):output} from Terraform remote state.

    
Adopts agents-cli deploys
An engine already deployed with the same display name is updated, not duplicated. agents-cli run and publish keep working.

    
Deploy as a service account
Impersonate a deployer per stage, from the CLI, an env var or provider.deployer. Workload Identity Federation in CI.

  






  
Where agentless fits

  
Keep Terraform for what's shared across an environment: APIs, the deployer, the state bucket, datasets and secrets used by several agents. agentless owns everything that belongs to one agent.
